## Fetching work

Use the connected Linear tools to fetch the referenced issue by its identifier or URL. Read its description, comments, and relevant linked documents. Scope searches and issue lists to the Nando project under Personal; team membership alone does not identify Nando work.

## Publishing work

When a skill says to publish to the issue tracker, create or update an issue in the Nando project under Personal. Write one issue per implementation ticket, with its scope, acceptance criteria, and relevant spec or repository links in the description. Link related issues and record dependencies through Linear's issue relationships.

When a skill produces a spec for the tracker, store it in a Linear document attached to Nando, and link implementation issues to it. Existing repository documentation remains a valid reference; include links when relevant.

Record ticket discussion in Linear issue comments. Use the label mapping in `triage-labels.md` for triage roles; labels are separate from Linear workflow statuses. Use the team's existing workflow statuses when changing implementation progress.

Use Linear as the source of truth for tickets. GitHub Issues and local `.scratch/` files are not this repo's issue tracker. If Linear is unavailable, report the access problem and retain any draft locally until it can be published to Linear.
